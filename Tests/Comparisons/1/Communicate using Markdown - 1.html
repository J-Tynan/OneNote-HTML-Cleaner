Organize ideas and collaborate using Markdown, a lightweight language for text formatting.

This course will walk you through creating and using headings more effectively, organizing thoughts in bulleted lists, and showing how much work you’ve completed with checklists. You can even use Markdown to add some depth to your work with the help of emoji, images, and links.
What you'll build: We'll update a plain text file and add Markdown formatting, and you can use this file to start your own GitHub Pages site.

Cues

Notes
  1. Course outline

In this course, using Markdown I will: Add headers, add an image, add a code example, make a task list and merge a pull request.
  1. What is Markdown?

Markdown is a lightweight syntax for communicating on GitHub. You can format text to add a heading, lists, bold, italics, tables, and many other stylings.
  1. File extensions?

Markdown files end with an extension of either .md or .markdown however I would aim to always use the .md extension.
  1. What is a header?

A header is a larger bit of text at the beginning of a section. There are six sizes.

# This is an `<h1>` header, which is the largest.

## This is an `<h2>` header.

###### This is an `<h6>` header, which is the smallest.
  1. Adding images

When adding images to Markdown always include descriptive text in the square brackets. This is important for users with screen readers and this text will be shown if the image fails to load. Example:
![Image of Yaktocat](https://octodex.github.com/images/yaktocat.png)

  1. Adding code blocks

GitHub's Markdown also supports code blocks, the colour of these change depending on the language. Example:
``` javascript

var myVar = "Hello, world!";

```
  1. Adding a task list

A Markdown task list creates checkboxes to check/tick off. You can only check/tick these boxes by editing the file. Example:
- [x] List syntax is required

- [x] This item is complete

- [ ] This item is not complete
  1. Merge the pull request(s)

Click on 'Merge pull requests' and delete the old branch.
  1. Recap of tasks

I have learned about Markdown, headings, images, code examples, and task lists. Also I have created a merged a GitHub Markdown file.
  1. Follow-up

You can enable GitHub Pages and see your Markdown file as a website!
  1. Publish README as website

Under your repository name at the upper right, click "Settings".

Then on the lower left, click 'Pages' in the 'Code and automation' section.

In the GitHub Pages section, ensure "Deploy from a branch" is selected from the Source drop-down menu, and then select main from the Branch drop-down menu as your GitHub Pages publishing source.

Click the 'Save' button.

Wait about 30 seconds then refresh the page. When you see "Your site is published at ..." you can click on the link to see your published site.

  • Creating Markdown files and merging pull requests are essential basic skills when using GitHub.
