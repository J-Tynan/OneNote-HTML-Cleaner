# Homepage Specification Approved for Implementation

This document records the approved homepage direction for OneNote HTML Cleaner.

## Approved Direction

The homepage will be designed as a compact workbench experience. It will primarily serve one-off and occasional users, with repeat and batch users supported through progressive disclosure.

The homepage must make the first successful conversion feel immediate, safe, and obvious.

## Approved Decisions

- Keep auto-convert on by default.
- Keep Advanced options collapsed by default.
- Lead with the outcome, not the mechanism.
- Make import the primary action and results the next stage.
- Keep ZIP download contextual to the results stage.
- Keep manual Convert visible but de-emphasized when auto-convert is on.
- Keep help concise on the homepage and deeper in the modal.
- Show clear trust signals near the main action, including local processing, supported input, and privacy.
- Use a compact workbench layout rather than a hero-heavy marketing layout.

## Content Direction

- The main heading should be outcome-oriented, such as converting exported OneNote pages.
- Supported input should be stated clearly in the main import area.
- The homepage should feel calm, professional, and trustworthy.
- Experimental features should remain clearly secondary to the stable HTML path.

## Implementation Baseline

This specification is approved as the implementation baseline. The next step is to draft the homepage wireframe model for UI and UX testing.
