## 1. Diagnosis of redesign attempt 1

**Planning problems**

- The plan treated markup preservation as a higher priority than the approved screenshot’s information architecture.
- It split visual work into eight narrow phases before first proving the approved shell. That allowed each phase to improve styling while retaining the old page model.
- Existing behavioral tests were used as a proxy for visual acceptance. They verify IDs, state, download behavior, and layout stability, but do not detect a card-heavy or vertically inefficient desktop layout.

**Implementation/decomposition problems**

- The current main branch still uses separate import, dropzone, and Advanced Options surfaces in a $7/5$ desktop grid. The approved reference needs one compact import card, a compact disclosure beneath it, and approximately equal desktop columns.
- The prior branch chain is linear (`New-UI-Phase-1` through `New-UI-Phase-8`) and provides rollback points, but its output should not be merged as a redesign base.
- `renderFileList()` retained a large rounded card for every entry. CSS refinement cannot make that convincingly resemble the approved table/tree-like result surface.

**Existing-code constraints**

- The constraints were real, but mostly presentation-safe: `ui.js` binds to IDs and delegates row actions through `data-remove-id` and `data-download-id`. That permits substantial HTML restructuring.
- One existing test actively preserves the failed structure: `header-edge-to-edge-playwright.js` requires import, separate dropzone, then Advanced Options. It must be deliberately updated in Milestone 1.

**CSS/layout problems**

- `lg:grid-cols-12` with `lg:col-span-7` / `lg:col-span-5` constrains the Results surface to the narrower column, causing filename pressure.
- `.file-item` is a padded, rounded, bordered card; `.file-item__actions` stacks actions vertically.
- `.option-panel`, `.option-subgroup`, `space-y-*`, descriptions under every option, and nested borders turn one disclosure into several visual subcards.
- The detached `#controls` dropzone consumes another full card-height block.
- Large primary button sizing and broad vertical gaps amplify the left-column height.

## 2. Structural gap analysis

**Current main / failed implementation**

- Header has title, description, Help icon, and theme control, but lacks the compact Documentation/Help action composition of the approved design.
- Left column is import card, separate dropzone card, then a tall Advanced Options card.
- Convert is colocated with Browse instead of operating as a compact queue action.
- Results actions precede the list, while the approved reference places bottom actions after the working surface.
- Results use individual cards rather than shared column headers and compact rows.
- Footer has a local-processing note and Documentation only.

**Approved screenshot**

- Uses a compact, balanced workbench: approximately equal columns, dense cards, import/drop integrated, one compact options disclosure, thin queue action area, and a row-based Results surface.
- Its hierarchy is visual only. Native notebook trees, counts, filters, selection, and bulk selection actions must not be copied.

**Required structural changes**

- Move `#dropzone` and `#fileInput` inside the import card while retaining `#controls` as a stable wrapper if useful.
- Move the existing `#convertButton` wrapper to a compact queue-action strip below Advanced Options.
- Replace the 7/5 grid with equal desktop tracks.
- Move Results actions below `#fileList`.
- Add static Results column headers in `index.html`; retain dynamic rows inside `#fileList`.
- Flatten Advanced Options into one disclosure with compact option rows and only conditionally visible dependent controls.

## 3. Behavioural contracts that must survive

Preserve these live hooks from `index.html` and `ui.js`:

- Import and drag/drop: `#importButton`, `#fileInput`, `#dropzone`, keyboard focusability, paste intake, drag-state styling.
- Conversion: `#convertButton`, `.convert-button-wrapper`, `#convertTooltip`, `#autoConvertEnabled`, auto/manual conversion semantics, queue status lifecycle.
- Results: `#statusPanel`, `#appStateBadge[data-state]`, `#statusSummary`, `#fileList`, `.file-item[data-id][data-status]`, `.status-pill--*`.
- Per-entry actions: `[data-remove-id]`, `[data-download-id]`, `.file-item__actions`; preserve delegated click handling.
- Downloads: `#downloadZip`, external-CSS single-download restriction, ZIP behavior.
- Persistence: queue draft restore, current settings persistence, status restoration.
- Advanced settings: `#externalizeCssEnabled`, `#externalizeCssMode`, `#experimentalExportEnabled`, `#exportFormat`, `#markdownFlavor`, `#markdownFlavorContainer`, `#convertedPageThemeToggleEnabled`, `#toolbarEnabled`, `#toolbarStyle`, `#toolbarStyleContainer`.
- Diagnostics/help/theme: `#diagnosticsPanel`, `#diagnosticsList`, `#diagnosticsCount`, `#helpButton`, `#helpModal`, `#helpCloseButton`, `#themeToggle`.
- Status-summary minimum-height preservation, which protects against action-row movement.

## 6. Milestone 2 plan — Results architecture

**Goal:** Replace card-per-file output with dense, real-state rows.

**Files:** `ui.js`, `index.html`, `styles.css`, `unsupported-file-playwright.js`, focused queue/download tests.

**Exact structural changes**

- Add a static desktop column header for Name, Type, Status, Size, and Actions.
- Make `#fileList` render compact `.file-item` CSS-grid rows.
- Give Name the flexible track; use stable compact tracks for type, status, size, and actions.
- Derive Type from real source kind/extension, show real formatted size, and use current status/tone state.
- Preserve full filename access through an accessible name/title while visually truncating long names.
- Render error/unsupported/download-restriction messages as a compact row detail spanning the data region only when present.
- Retain `.file-item`, `data-id`, `data-status`, `.status-pill--${tone}`, `.file-item__actions`, `[data-remove-id]`, and `[data-download-id]`.

**Behaviour preserved:** removal, downloads, ZIP export, status/error/unsupported state, persistence, keyboard access, conversion semantics.

**Non-goals:** native indentation, notebook/page hierarchy, selection controls, fake rows, fake metadata.

**Tests:** Milestone 1 suite plus `convert-button-smoke-playwright.js`, `unsupported-file-playwright.js`, `queue-reload-restore-playwright.js`, `queue-focus-preservation-playwright.js`, and `npm run test:ui-download-smoke`.

**Manual tests:** long MHT/MHTML names, queued/success/error/unsupported rows, Remove, per-file Download, ZIP, restored queue.

**Visual acceptance:** no large rounded file cards; filenames remain mostly one line; results visibly read as rows with shared columns.

**STOP/GO:** stop for screenshot, behavioral check, and diff review before styling work.

**Risk:** tests that query old nested row paragraphs. Change them to assert semantic row text/status rather than specific incidental tags.

**Recommended model:** GPT-5.6 Terra, default/adaptive, standard context.

**Commit boundary:** `ui-attempt-2/m2-results`, branched from approved Milestone 1.
